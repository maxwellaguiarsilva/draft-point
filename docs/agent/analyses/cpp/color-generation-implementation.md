## 4. Implementation

The function lives in the anonymous namespace of the test file. It is not domain-independent enough to belong in `sak` (it encodes the concept of a color palette), but it composes exclusively from `sak` primitives.

### `subdivision_value`

Maps a channel index to a normalized value in `[0, 1]` via the spatial subdivision sequence:

```cpp
constexpr auto subdivision_value( byte index ) -> float
{
	if( index == 0 )
		return	0.0f;
	if( index == 1 )
		return	1.0f;
	float result = 0.0f;
	float weight = 0.5f;
	for( auto remaining = index - 1; remaining > 0; remaining >>= 1 )
	{
		result += weight * ( remaining & 1 );
		weight *= 0.5f;
	}
	return	result;
}
```

### `deinterleave`

Extracts the per-channel index for a given dimension by gathering bits at strided positions:

```cpp
constexpr auto deinterleave( byte index, size_t dimension, size_t dimensions ) -> byte
{
	byte channel_index = 0;
	for( size_t source_bit = dimension, dest_bit = 0; source_bit < 8; source_bit += dimensions, ++dest_bit )
		channel_index |= static_cast< byte >( ( ( index >> source_bit ) & 1 ) << dest_bit );
	return	channel_index;
}
```

### `create_color`

The dimension-agnostic entry point. Deinterleaves the index across dimensions, maps each channel through the subdivision sequence, and materializes the result into a point:

```cpp
template< is_point t_point >
auto create_color( byte index, float min_value = 0.0f, float max_value = 1.0f ) -> t_point
{
	constexpr size_t dimensions = t_point{ }.size( );
	const float range = max_value - min_value;

	auto calc_channel = [ = ]( size_t dimension ) -> float
	{
		const byte channel_index = deinterleave( index, dimension, dimensions );
		return	min_value + subdivision_value( channel_index ) * range;
	};

	return	iota( 0uz, dimensions ) | transform( calc_channel ) | to;
}
```

The terminal `| to` is `sak::ranges::to` (a native `range_adaptor_closure`), imported into the call site — see the [design document](dimension-agnostic-color-generation.md) §3.

### Breakdown

1. **Dimension discovery:** `t_point{ }.size( )` extracts the dimension count at compile time from the point type itself.
2. **Channel calculation:** `calc_channel` deinterleaves the index for the given dimension, then maps the resulting channel index through `subdivision_value` and scales it into `[min_value, max_value]`.
3. **Point construction:** `iota( 0, dimensions ) | transform( calc_channel ) | to` generates the dimension indices, transforms each into a channel value, and materializes the result into a `t_point` via `sak::ranges::to`. Because `to` is a `range_adaptor_closure`, the whole pipeline routes through the STL's native `operator|` — no `sak::operator|` ADL is involved. `point` needs a `std::from_range_t` constructor for `to` to build it (already present in `point.hpp`, see range-pipeline §3.3).

## 5. Usage in the Test

A single color is generated by calling `create_color` with an explicit point type:

```cpp
const auto color = create_color< vec3 >( index );
```

A list of colors is generated by mapping over an iota range:

```cpp
auto make_color = [ ]( size_t index ) -> vec3 { return create_color< vec3 >( static_cast< byte >( index ) ); };
const vector< vec3 > colors = iota( 0uz, total ) | transform( make_color ) | to;
```

The `static_cast< byte >` adapts the `size_t` produced by `iota` to the `byte` parameter of `create_color`. The terminal `| to` is `sak::ranges::to`, whose proxy materializes into the declared `vector< vec3 >` type on assignment; `to` must be imported via `__using( ::sak::ranges::, to )` (the closure itself, not `std::ranges::to`, which would require naming `vector< vec3 >` mid-pipeline).

## 6. Properties

| Property | Description |
|---|---|
| **Dimension-agnostic** | Works unchanged for `vec2`, `vec3`, `vec4`, or any `point<T, N>`. The dimension count is deduced from the type parameter, and bit deinterleaving generalizes automatically. |
| **Extremes first** | The first `2^N` colors are the corners of the N-dimensional unit hypercube — the maximally distinct set. This is superior to the base-N approach, which produced permutations of two mid-range values. |
| **Recursive subdivision** | After the corners, the sequence fills edge midpoints, then face centers, then interior points, maintaining maximum distance between consecutive colors. |
| **No `sak/math` modifications** | Uses only existing `sak` primitives (`is_point`, `sak::ranges::to`). No math niebloids are needed — the mapping is purely bitwise. (`point` already carries the `std::from_range_t` constructor `sak::ranges::to` relies on.) |
| **Declarative** | The outer structure is a pipeline (`iota | transform | to`). The bit manipulation helpers (`subdivision_value`, `deinterleave`) are named, reusable, and `constexpr`. |
| **Scalable** | The `byte` index supports up to 256 colors. For 3 dimensions, each channel gets 3 bits (8 values); for 2 dimensions, 4 bits (16 values). Extending to larger palettes requires only widening the index type. |
